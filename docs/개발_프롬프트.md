# Claude Code 단계별 개발 프롬프트

요구사항 정의서 v0.3을 기준으로, Claude Code에 **한 단계씩** 붙여넣어 쓰는 프롬프트 모음이다.

## 시작 전 준비

1. 빈 폴더(또는 GitHub 저장소)를 만들고 Claude Code를 연다.
2. 다음 파일을 넣는다.
   - 저장소 루트: `CLAUDE.md` (함께 드린 파일)
   - `docs/`: `새한프라텍_출고재고보드_요구사항정의서_v0.3.docx`
   - `docs/sample/`: 기업에서 받은 기존 Claude 데모 코드와 샘플 데이터 (받은 경우)
3. 아래 단계를 순서대로 진행한다. 각 단계가 끝나면 결과를 직접 확인하고 커밋한 뒤 다음 단계로 간다.

사용 팁

- 각 단계는 **플랜 모드**(Shift+Tab)로 먼저 계획을 받고, 계획이 맞으면 실행을 승인한다.
- 한 단계에 문제가 생기면 다음 단계로 넘어가지 말고 그 자리에서 고친다.
- 기업 답변(9장 Q1~Q13)이 오면 "부록. 확인 사항 반영 프롬프트"를 사용한다.

---

## 0단계. 정의서 정리와 개발 계획

```
docs/ 폴더의 요구사항 정의서(docx)를 pandoc으로 docs/requirements.md로 변환해 줘.
그 다음 CLAUDE.md와 requirements.md를 읽고 아래를 정리해 줘. 코드는 아직 쓰지 마.

1. FR-01~FR-18, NFR-01~NFR-09를 표로 정리하고, 각 항목을 어느 개발 단계에서 구현할지 배정
2. 정의서 9장 미확정 사항(Q1~Q13) 중 개발을 막는 것과, 임시 가정으로 진행할 수 있는 것을 구분하고 각각의 임시 가정
3. docs/sample/에 데모 코드나 샘플 데이터가 있으면 분석해서 ERP 데이터의 실제 컬럼, 갱신 방식, 사업장 구분 여부를 정리

결과는 docs/개발계획.md로 저장해 줘.
```

## 1단계. 프로젝트 뼈대와 데이터 모델

```
CLAUDE.md의 기술 스택대로 프로젝트를 만들어 줘.

- Next.js + TypeScript + Tailwind + Prisma(Supabase PostgreSQL). 배포는 Vercel, DB는 Supabase. Docker는 쓰지 않는다.
- 정의서 5장 데이터 정의를 Prisma 스키마로 옮겨 줘:
  품목 재고 스냅샷(5.1), 재고 변동(5.2), 생산 계획·공정(5.3), 상담 메모(5.4), 사용자·역할, 연동 기록(성공/실패 시각)
- 사업장 필드는 모든 재고·변동·계획에 넣어 줘.
- docs/sample/ 데이터가 있으면 그걸로, 없으면 용기 제조사다운 품목 30개로 샘플 시드를 만들어 줘.
- 출고 가능 수량 계산을 src/lib/domain/에 순수 함수로 만들고 단위 테스트를 써 줘.
  (예: ERP 100, 불량 10 적용 중 → 90 / 해제된 변동은 제외 / 결과가 음수면 0 + 경고 플래그)

완료 기준: .env에 Supabase 접속 정보를 넣고 prisma migrate dev + db seed가 성공하고, npm test가 통과한다.
```

## 2단계. 재고 조회 화면 (P0: FR-01~FR-06)

```
영업사원용 재고 조회 화면을 만들어 줘. 휴대폰 세로 화면이 기준이야. 정의서 6.1을 따라.

- FR-01 로그인 (미등록 계정 차단)
- FR-02 재고 목록: 품목명·규격, 오른쪽에 출고 가능 수량을 크게
- FR-03 검색: 품목명·규격 부분 일치, 띄어쓰기 무시, 1초 이내
- FR-04 품목 상세: ERP 재고, 차감 내역, 출고 가능 수량
- FR-05 상단 기준 시각 + 오래된 데이터 경고
- FR-06 사업장 필터 (설정으로 켜고 끄기)

IT 초급 사용자가 설명 없이 쓸 수 있게 단순하게 만들어 줘.
각 FR의 완료 기준을 Playwright 테스트로 작성하고 통과시켜 줘.
```

## 3단계. 변동 입력 화면 (P1: FR-07, FR-08)

```
생산지원팀용 변동 입력 화면을 만들어 줘. 사무실 PC 기준이야. 정의서 6.2를 따라.

- 품목 검색 → 유형(불량/보류/출고 예정/기타), 수량, 사유 입력 → 저장 즉시 출고 가능 수량에 반영 (FR-07)
- "적용 중인 변동" 목록에서 해제 (FR-08). 해제해도 기록은 남기고 이중 차감이 없어야 해.
- 입력자·시각 기록, editor 이상 권한만 접근
- 엑셀로 변동을 일괄 등록하는 기능은 docs/sample/에 엑셀 양식이 있을 때만 만들어 줘.

시나리오 3.2(불량 10개 발견 → 100에서 90으로)를 E2E 테스트로 만들어 줘.
```

## 4단계. ERP 연동 에이전트 (P1: FR-09, FR-10)

```
ERP 연동을 만들어 줘. 정의서 7장 구조를 따라. ERP 추출 방식(Q1)은 아직 미정이야.

- src/lib/erp/에 ErpSource 인터페이스를 만들고, 구현체는 CsvFileSource(지정 폴더의 최신 엑셀/CSV를 읽음)와 MockSource 두 개만 먼저 만들어 줘.
- agent/에 사내에서 실행할 연동 에이전트를 만들어 줘:
  매일 09:00 기초재고, 이후 15분마다 읽어서 서버 API로 HTTPS 전송, API 토큰 인증,
  실패 시 자동 재시도, 로그 파일 기록, Windows 서비스로 등록하는 방법 포함
- 서버에는 재고 수신 API와 연동 기록 저장을 만들어 줘.
- FR-10: 2회 연속 실패하면 관리자에게 메일 알림(SMTP 설정은 .env).
- 담당자 PC가 꺼져도 서버의 조회 화면은 계속 동작하고, 기준 시각 경고만 뜨는 걸 테스트로 확인해 줘.

docs/sample/의 기존 데모가 데이터를 가져오는 방식이 있으면 그 방식을 DbSource 등으로 옮기는 계획도 따로 정리해 줘.
```

## 5단계. 생산 예정·공정·상담 메모 (P1/P2: FR-14~FR-18)

```
추가 생산 예정과 상담 메모 기능을 만들어 줘. 정의서 3.4, 5.3, 5.4, 6.3, 6.4를 따라.

- FR-16 생산 계획·공정 입력 화면(생산지원팀, PC): 품목·수량·착수/완료 예정일·공정 단계 등록·수정, 엑셀 생산계획 업로드
- FR-14 영업사원 품목 상세에 "생산 예정"(완료 예정일·수량) 표시, 목록의 출고 가능 수량 옆에 "추가 생산 예정" 표시
- FR-15 공정 단계(계획/사출 중/검사 중/완료)와 마지막 변경 시각. 단계 목록은 설정으로 바꿀 수 있게 (Q12 미정)
- 날짜는 항상 "예정"으로 표시
- FR-17 상담 메모(영업사원, 모바일): 고객명·요청 수량·희망 납기(달력)·내용, 1분 안에 입력 가능하게
- FR-18 생산지원팀용 "고객 요청" 모아보기: 품목·희망 납기 순, 희망 납기가 완료 예정일보다 빠르면 강조
- NFR-09 상담 메모는 영업팀·생산지원팀만 열람, 수정·삭제 이력 저장

시나리오 3.4를 E2E 테스트로 만들어 줘.
```

## 6단계. 관리 기능과 품질 점검 (P2: FR-11~FR-13, NFR 전체)

```
남은 기능과 비기능 요구사항을 마무리해 줘.

- FR-11 즐겨찾기, FR-12 변동 이력(최근 90일), FR-13 사용자 관리(계정 생성·권한·즉시 차단)
- NFR-01 가용성(Vercel·Supabase 관리형 서비스 기준, 상태 확인 API), NFR-03 HTTPS·접속 기록, NFR-05 첫 화면 3초·검색 1초,
  NFR-08 매일 DB 백업 스크립트와 1년 보관
- 정의서의 모든 FR/NFR을 표로 다시 점검해서 구현 여부, 테스트 여부, 남은 일을 docs/점검표.md로 정리해 줘.
```

## 7단계. 배포와 인수인계 문서

```
운영 배포와 인수인계 문서를 준비해 줘.

1. 배포: Vercel + Supabase 설치 절차(GitHub 연결, 환경 변수, 도메인, Vercel Cron, Supabase 백업)와 사내 연동 에이전트 설치 절차를 docs/배포가이드.md로 작성
2. 운영 매뉴얼(NFR-07): 연동 에이전트 재시작, 연동 실패 알림 대응, 백업 복구, 계정 관리, 자주 묻는 문제를 docs/운영매뉴얼.md로 작성
3. 인수인계서: docs/인수인계서_초안.docx(함께 받은 양식)의 [ ] 빈칸을 실제 값(접속 주소, 서버 위치, 관리자 계정 담당자, 연동 주기 등)으로 채우고,
   실제 화면 캡처를 넣어 docs/인수인계서.docx로 만들어 줘. 비밀번호와 토큰 값은 문서에 넣지 말고 "별도 전달"로 적어 줘.
```
